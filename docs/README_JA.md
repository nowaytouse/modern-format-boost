## Modern Format Boost とは？

**Modern Format Boost** は、Rust ベースの高性能メディア最適化エンジンです。メディアドメインごとに処理を分割します：

- `img`: **静止画のみ**を処理
- `vid`: **動画およびアニメーションメディア**を処理

現在の実装における典型的なルートは以下の通りです：

- 📸 **静止画 (`img run` メイン CLI パス)**: JPEG → JXL 可逆再構築。PNG/TIFF/BMP およびその他の可逆静止画 → JXL。非可逆のモダン静止画は通常スキップされます。アニメーションまたはアニメーションの可能性がある入力は無視されます。
- 🎬 **動画**: H.264 およびその他の非ターゲットコーデックは HEVC/AV1 品質検索を通過します。コーデック/コンテナの選択は `--codec` と `--apple-compat` に依存します。
- 🎞️ **アニメーションメディア**: GIF/WebP/AVIF/APNG/HEIC/HEIF/JXL アニメーションのルーティングは、`vid` と共有の `loop_intent` ポリシーによって管理されます。

これは、無意識な品質低下よりも、誠実なスキップ/無視を好む保守的なオプティマイザーです：

- 🍎 **Apple エコシステム優先**: 完全な Apple 互換モード、Live Photo 検出、AAE サイドカー処理に対応。
- 🔒 **メタデータの守護者**: EXIF、XMP、ICC プロファイル、作成日時、macOS xattrs、Finder タグを保持。
- ⚡ **体感速度の最適化**: 「Deep-First」ソート戦略。より深いディレクトリレベルを優先し、次にファイルサイズと形式でソートすることで、効率的なバッチ処理と最大の処理能力を確保します。
- 🎞️ **HDR10+ 動的メタデータ**: サイドカーの抽出と x265 SEI インジェクションにより、SMPTE 2094-40 メタデータを完全に保持。
- 🌅 **HDR ゲインマップ合成**: Apple/Samsung/ISO HEIC ゲインマップから高忠実度な 32 ビットリニア HDR バッファを自動的に合成し、JXL への変換時に最大のダイナミックレンジを維持します。
- **🔍 ベンダーメタデータの認識**: HEIC ファイル内の Samsung/Google 固有の XMP ネームスペースをインテリジェントにスキャンし、コンテキストの最大保持を実現します。

## ⚠️ 免責事項と重要な注意点

1. **データ安全第一**: 潜在的なデータ損失を避けるため、元のファイルを上書きする（`--in-place`）のではなく、別のディレクトリに出力する（例：`-o /path/to/output`）ことを強くお勧めします。特にかけがえのないメディアについては注意してください。
2. **ベータソフトウェア**: このプログラムは広範囲にテスト、デバッグ、最適化されており、画質やデータの損失を防ぐように設計されていますが（変更履歴参照）、100% バグがないことを保証するものではありません。問題が発生した場合は GitHub で報告してください。
3. **計算の負荷**: 効率化（特に Apple Silicon M シリーズ）のために最適化されていますが、`--ultimate` モードで大量のバッチを処理する場合は時間がかかることがあります。長時間システムリソースを占有するため、計画的にタスクを実行してください。
4. **ツールの成熟度**: 統合ツール（`img`, `vid`）のデフォルトは HEVC です。これは AV1 戦略よりも成熟しており安定しています。高い信頼性が必要な実用タスクには HEVC（デフォルト）を推奨します。

## 🔒 プライバシーとデータの整合性

**Modern Format Boost** は「ローカルファースト」アーキテクチャで構築されており、クリエイティブな資産が完全にあなたの管理下に留まることを保証します。

- **オフライン動作**: 100% オフライン処理。テレメトリ、利用状況追跡、クラウドへの問い合わせは一切ありません。コアバイナリにはネットワーク関連のコードは含まれていません。
- **Rust による堅牢なランタイム**: Rust で構築されており、メモリ破壊バグ（バッファオーバーフローなど）をネイティブに排除します。
- **安全な統合**: すべての外部ツール（FFmpeg, cjxl）は、生のシェル実行ではなく、安全にエスケープされたプリミティブを介して呼び出され、任意のコマンドインジェクションを防止します。
- **パスの分離**: 高度な正規化により、ディレクトリトラバーサルを防ぎ、無関係なシステムファイルを保護します。
- **システムパスのブロックリスト**: 機密性の高いシステムディレクトリに対する保護機能が組み込まれており、誤った OS ファイルの変更を防止します。
- **動的リソース調整**: メモリ/CPU の負荷に基づいて処理スレッドを自動的に調整し、過酷なタスク中のシステムクラッシュを防止します。
- **包括的なメタデータ管理**: EXIF、XMP、ICC、およびファイルシステムのタイムスタンプ（btime/mtime）を厳密に保持します。
- **安全な処理とセッションの隔離**:
  - **ワークスペースを汚さない**: 中央集中型の追跡 (`~/.mfb_progress/`) により、メディアフォルダを 100% クリーンに保ちます。写真/動画の間に隠しメタデータファイルが残ることはありません。
  - **競合のない一時ファイル**: すべての中間分析ファイル（YUV ストリーム、分析セグメント）は、ランダムな UUID で一意に識別されます。これにより、複数インスタンスの衝突を防ぎ、クリーンアップ時の「外科的精度」を保証します。
  - **開始時のクリーンアップ**: タスクが正常に完了した場合でも、中断後に再開された場合でも、システムはすべての過渡データを自動的に消去します。この「自己修復」アーキテクチャにより、ディスクに残骸が残ることはありません。
  - **インテリジェントなチェックポイントリセット**: ユーザーが手動で出力ディレクトリを削除して「最初からやり直す」ことを自動的に検出し、再開モードであってもフルリセットをトリガーします。

## 🛠️ 技術詳細：仕組み — パイプライン

### 画像パイプラインのロジック

すべてのファイルは、マルチステージの意思決定パイプラインを通過します：

- **ステージ 1 — スマート検出**: JPEG DQT テーブル（UltraHDR ゲインマップ検出）、WebP VP8L チャンク、AVIF `av1C` ボックスをバイナリレベルで分析します。現在、100% Clippy 準拠の **Zero-Debt Architecture** と堅牢な `OpenEXR`/`JPEG 2000` ヘッダー解析を備えています。
- **ステージ 2 — ルートとエンコード**: JPEG には JXL VarDCT（ビット完全）、可逆ソース（PNG、可逆 WebP/AVIF/HEIC/EXR/JP2）には Modular モードを使用します。
- **ステージ 3 — 迂回経路**: TIFF/WebP/BMP/HEIC などの形式は、画質を損なうことなく `cjxl` 互換性を確保するため、一時的に 16 ビット PNG または **32 ビット OpenEXR** に前処理されます（8/16/32 ビット対応パイプライン）。
- **ステージ 4 — HEIC HDR 合成**: ゲインマップ（Apple/Google）を含む HEIC ファイルをインターセプトし、中間 **OpenEXR** エスコートパイプラインを介して 32 ビットリニアライト HDR バッファを合成し、真の HDR JXL 出力を提供します。
- **ステージ 5 — 静止画/アニメーションの分割**: `img` は現在、アニメーションまたはアニメーションの可能性がある資産を拒否します。アニメーション化されたモダンフォーマットは、静止画パイプライン内で変換されるのではなく、`vid` に委譲されます。
- **ステージ 6 — Loop Intent v3**: 共有の loop-intent ロジックにより、アニメーションメディアを GIF のように維持するか、ビデオパイプラインで処理するかを決定します。Apple 互換のモダンアニメーション配信ポリシーはここに集約されています。

### ビデオパイプライン：三段階の飽和検索

1. **フェーズ 1: GPU 粗検索**: ハードウェアエンコーダ（VideoToolbox/NVENC）でバイナリ検索を行い、「品質の屈曲点（quality knee）」を見つけます。
2. **フェーズ 2: CPU 微調整**: GPU CRF を `x265` スケールにマッピングします。「**Sprint & Backtrack**」（成功時に 2 倍のステップ、超過時に 0.1 にリセット）を使用します。
3. **フェーズ 3: 究極の 3D 品質ゲート**: VMAF-Y ≥ 86.0（動的ベースライン相対の最低基準）、CAMBI ≤ 6.0（バンディング）、PSNR-UV ≥ 30.0 dB（彩度の最低基準）の同時パスを要求します。
   - **フュージョンスコアリング**: MS-SSIM + SSIM_All（0.6/0.4 重み付け）を組み合わせて、堅牢な構造分析を行います。
   - **彩度ガード**: libvmaf MS-SSIM がクラッシュする可能性のある低解像度を自動的に検出し、Y のみのスコアリングにフォールバックして処理の信頼性を確保します。
   - _注意: `--ultimate` モードでは、画質の向上がゼロであることを示す **50 個の連続サンプル**が得られるまで検索を終了せず、絶対的な飽和を保証します。_

### メタデータと HDR の保持

- **HDR**: bt2020 プライマリ、PQ/HLG TRC、および Mastering Display メタデータを保持します。
- **Dolby Vision**: `dovi_tool` を介して RPU を抽出し、x265 に注入します（Profile 7 → 8.1 変換）。
- **macOS xattrs**: `copyfile` と `setattrlist` を介して Finder タグ、追加日、および作成日時を保持します。

### `img` ルーティングに関する注意

現在、リポジトリには 2 つの画像変換エントリポイントがあります：

- `img run` / `crates/img/src/main.rs` のバッチ CLI パス
- `crates/img/src/conversion_api.rs` のライブラリヘルパー `smart_convert()`

これらは現在、**完全には一致していません**。

- メイン CLI パスは、現在受け入れられている静止画変換に対して JXL 指向です。
- 古いヘルパー API には、一部の非 JPEG 非可逆静止画に対する AVIF ターゲットブランチがまだ含まれています。
- `img` CLI も `--codec` をパースしますが、現在の静止画バッチパスでは、そのフラグは実際のルーティング決定を実質的に変更しません。

この README は、通常のバッチ使用でユーザーが遭遇する **現在の CLI/ランタイムの動作を優先して** 説明しています。

### HDR 形式戦略

| HDR タイプ            | 検出                                     | 保持戦略                                                                               |
| :-------------------- | :--------------------------------------- | :------------------------------------------------------------------------------------- |
| **HDR10**             | side_data の mastering_display + max_cll | FFmpeg 引数を介して静的メタデータを完全に保持                                          |
| **HEIC ゲインマップ** | HEIC 補助画像 (Apple/Samsung/ISO)        | 32 ビットリニア HDR -> JXL (真の HDR) に合成                                           |
| **UltraHDR JPEG**     | JPEG APP1/APP2 + XMP (hdrgm:)            | メタデータは保持されますが、ゲインマップ損失の警告が出力されます                       |
| **HLG**               | color_trc = arib-std-b67                 | カラープライマリ + TRC を保持                                                          |
| **Dolby Vision**      | ストリーム/フレーム内の DOVI side_data   | `dovi_tool` による RPU 抽出 → x265 注入。Profile 7 → 8.1 変換                          |
| **HDR10+**            | ST2094-40 動的メタデータ                 | `hdr10plus_tool` サイドカー抽出と x265 注入によるサポート (Profile A/B メタデータ保持) |
| **SDR**               | HDR マーカーなし                         | 標準処理 (yuv420p)                                                                     |

### 🗄️ データベース設定

Modern Format Boost は、必須のローカルキャッシュおよび品質推論エンジンとして PostgreSQL（`pgvector` 拡張機能付き）を使用します。`img` と `vid` のバイナリは起動時にデータベースに接続するため、データベースサービスに接続できない場合はエラーとなり、プログラムが終了します。

#### 1. PostgreSQL サービスの起動

- **macOS**: `brew services start postgresql`

## 🚀 使い方

### クイックスタート

```bash
# 画像パスの変換
img run /path/to/media
# 動画パスの変換
vid run /path/to/media

# AV1 戦略を使用する場合:
vid run --codec av1 /path/to/media
```

### ⚡ 高速モードとスマートレジューム

**高速モード** (`fastmode`) は、ドラッグアンドドロップ UI ワークフロー (`crates/dev/src/bin/drag_and_drop_processor.rs`) 向けに調整されており、高信頼性の再開機能を提供します。

- **`WorkingCopyMarker` 状態管理**: 中断時も安全に部分的な処理の進行状況を追跡します。
- **古いソースの検出**: 元のファイルが変更された場合、自動的に検出して再構築を強制し、安全でない再試行を回避します。
- **Fail-Closed 保護**: 深いコンテキストのキャプチャと `Blake3` 検証により、`img run` 中断時にもファイルの破損が一切発生しないことを保証します。

### 詳細オプション

- `--ultimate`: アーカイブ級の **0.01 精度** 検索（高品質、高時間コスト）。
- `--apple-compat`: Apple エコシステム互換性（Live Photos/AAE）を有効にします。CLI のデフォルトはオンです。`--no-apple-compat` で無効化できます。
- `--in-place`: 元のファイルを置き換えます。**警告：取り消し不能。**
- `-o /dir`: 安全な出力ディレクトリ。（推奨）
- `--verbose`: 詳細な処理ログを表示します。
- `--no-recursive`: サブディレクトリを探索しません。
- `--force-video`: Loop Intent に関係なく、アニメーション画像をビデオとして強制的に処理します。

### 高度なサブコマンド

- `img cache-stats`: SQLite 分析キャッシュの統計を表示します。
- `vid strategy <file>`: 特定のファイルのパイプライン戦略をプレビューします。
- `img restore-timestamps`: ファイル名のパターンに基づいて作成日を一括修正します（メタデータ復旧）。

### 💡 マルチインスタンスに関する注意

**Modern Format Boost** は、複数のウィンドウ/インスタンスの実行をネイティブにサポートしています。

- **並列処理**: 異なるパスを独立して処理するために複数のウィンドウを実行できます。
- **注意**: ハードウェアの I/O パフォーマンスに応じてスケールしてください。過度な並列実行はファイルシステムの競合を引き起こす可能性があります。

## 🏗️ アーキテクチャ

### CI/CDとテストゲートシステム

Modern Format Boostは、コアアーキテクチャのゼロ負債を保証するために厳格な品質ゲートシステムを使用しています。

- **Rust-first開発ツールチェーン**：エンジニアリングの入口は `crates/dev/src/bin` 配下のRustバイナリです。Python原本は、安全に削除できることが確認されるまで互換参照として残します。
- **ローカルCI検証**：開発の前に、必ず`just fix-gate`または`cargo run --locked -p dev --bin check_all -- --allow-non-nightly`を使用してチェックしてください。これは、コードのフォーマット、静的チェック、および自動テストの「信頼できる唯一の情報源」（SSOT）です。
- **テストの強化と安定性**：マルチプラットフォーム全体で完全な診断情報を収集するために、「Fail Fast」を無効にしました。また、画像（JPEG復元の検証など）のエラー状態に対する深いコンテキストキャプチャが追加されました。

### コア構造

- `crates/img/`: 静止画オプティマイザー（現在の CLI パスでは `JXL` / スキップ / 無視）
- `crates/vid/`: 動画およびアニメーションメディアオプティマイザー（`HEVC` / `AV1` / `GIF`）
- `crates/foundation/`: コアブレイン（GPU/CPU ハイブリッドエンジン、HDR マッピング、メタデータ）
- `Modern Format Boost.app/`: macOS ドラッグアンドドロップ UI

## ❓ FAQ

**1. JXL は広くサポートされていますか？**
macOS 14+ / iOS 17+、Chrome 91+、Firefox 128+ でネイティブサポートされています。ただし、既知のエコシステムの問題があります：

- **アニメーション**: モダンなアニメーション形式（JXL/AV1/HEIF）は、特に iCloud 経由で同期された場合、ネイティブの macOS/iOS 写真アプリや Finder でアニメーションとしてプレビューできない（静止画のみになる）ことがよくあります。モダンなブラウザや専用ツールでは正しく再生されます。
- **サムネイル**: **グレースケール ICC プロファイル**を使用している JXL ファイルは、開いたときは完璧にレンダリングされますが、Finder/iCloud で**黒いサムネイル**として表示されることがあります。
  JXL は、ビット精度のアーカイブや高忠実度な HDR 保存に依然として優れた形式です。

**2. HDR10+ はどのように処理されますか？**
完全にサポートされています。`hdr10plus_tool` を使用して SMPTE 2094-40 動的メタデータを抽出し、`libx265` の `--dhdr10-info` パラメータを介して HEVC ストリームに戻します。この機能を有効にするには、ツールがインストールされていることを確認してください。

**3. なぜ WebP/AVIF/HEIC をスキップするのですか？**
静止画の非可逆 WebP/AVIF/HEIC/HEIF は、すでにモダンな非可逆形式であるため、再エンコードしてもわずかなメリットに対して世代劣化のリスクがあるため、通常はスキップされます。現在のコードにおける重要な例外は以下の通りです：

- 可逆のモダン静止画は JXL に変換可能
- HEIC/HEIF ゲインマップ資産は HDR JXL に合成可能
- アニメーション化されたモダン形式は `img` では処理されず、`vid` と `loop_intent` を介してルーティングされます
