## Что такое Modern Format Boost?

**Modern Format Boost** — это высокопроизводительный движок для оптимизации медиафайлов, написанный на Rust. Он конвертирует устаревшие форматы изображений и видео (JPEG, PNG, H.264, VP9…) в современные кодеки (**JPEG XL** для изображений, **HEVC/AV1** для видео), обеспечивая значительное уменьшение размера файлов при сохранении или даже побитовом соответствии оригинальному качеству.

Это «умный компрессор», который **никогда не ухудшает качество ваших файлов**:

- 📸 **Изображения**: JPEG → JXL (без потерь, побитовое соответствие, размер меньше на ~20%); PNG/WebP/TIFF/HEIC → JXL.
- 🎬 **Видео**: H.264/VP9/AV1 → HEVC с поиском оптимального качества с аппаратным ускорением (GPU).
- 🍎 **Приоритет экосистеме Apple**: Полная совместимость с Apple, обнаружение Live Photo, обработка сопутствующих файлов AAE.
- 🔒 **Защита метаданных**: Сохранение EXIF, XMP, ICC-профилей, меток времени создания, macOS xattrs и тегов Finder.
- ⚡ **Оптимизация скорости**: Стратегия сортировки «Deep-First» — сначала обрабатываются файлы в самых глубоких папках, затем файлы сортируются по размеру и формату для обеспечения максимальной производительности.
- 🎞️ **Динамические метаданные HDR10+**: Полное сохранение метаданных SMPTE 2094-40 путем извлечения и последующей инъекции в поток x265.
- 🌅 **Синтез HDR Gainmap**: Автоматический синтез высокоточных 32-битных линейных HDR-буферов из Gainmap Apple/Samsung/ISO в файлах HEIC для сохранения максимального динамического диапазона при конвертации в JXL.
- **🔍 Метаданные производителей**: Интеллектуальное сканирование специфичных для Samsung/Google пространств имен XMP в файлах HEIC.

## ⚠️ Важные примечания

1. **Безопасность данных**: Чтобы избежать потери данных, настоятельно рекомендуется сохранять обработанные файлы в отдельную папку (например, используя `-o /path/to/output`), а не использовать перезапись оригиналов (`--in-place`).
2. **Бета-версия**: Программа прошла тщательное тестирование, но стабильность на 100% не гарантируется. Сообщайте об ошибках на GitHub.
3. **Ресурсозатратность**: Режим `--ultimate` обеспечивает максимальное качество, но требует значительного времени и системных ресурсов.
4. **Стабильность инструментов**: Унифицированные инструменты (`img`, `vid`) по умолчанию используют стратегию HEVC, которая на данный момент является более зрелой и стабильной, чем стратегия AV1. Для задач с высокими требованиями к надежности рекомендуется использовать стратегию HEVC (установлена по умолчанию).

## 🔒 Конфиденциальность и целостность данных

**Modern Format Boost** работает по принципу «Local-First» — ваши файлы остаются под вашим полным контролем.

- **Автономная работа**: 100% оффлайн-обработка. Никакой телеметрии или облачных запросов.
- **Безопасность Rust**: Использование Rust предотвращает ошибки работы с памятью (переполнение буфера и т.д.).
- **Изоляция путей**: Продвинутая нормализация путей защищает системные файлы от случайного изменения.

### Конвейер обработки изображений

- **Этап 1 — Определение**: Анализ таблиц JPEG DQT (UltraHDR), чанков WebP и коробок AVIF на бинарном уровне.
- **Этап 2 — Кодирование**: Использование JXL VarDCT для JPEG (побитовое соответствие) и Modular-режима для источников без потерь (PNG и др.).
- **Этап 3 — Транзит**: TIFF/HEIC временно преобразуются в 16-битный PNG или 32-битный OpenEXR для обработки без потерь качества.
- **Этап 4 — Синтез HDR HEIC**: Перехватывает файлы HEIC с картами усиления (Apple/Google) и синтезирует высокоточные 32-битные линейные HDR-буферы через промежуточный конвейер **OpenEXR**, обеспечивая истинный HDR JXL на выходе.
- **Этап 5 — Анализ намерений цикла (Loop Intent v3)**: Современный движок на базе 7-уровневого дерева решений. Оценивает **Loop Closure**, **Motion Gini**, **периодичность** и **KNN-взвешенное слияние** для идентификации зацикливания (мемы, стикеры, циклы).

### Конвейер видео: Трехфазный поиск

1. **Фаза 1: Грубый поиск GPU**: Бинарный поиск на аппаратных энкодерах для нахождения «колена качества».
2. **Фаза 2: Тонкая настройка CPU**: Масштабирование CRF GPU в шкалу `x265`.
3. **Фаза 3: Контроль качества**: Проверка по метрикам VMAF-Y ≥ 92.0, CAMBI ≤ 6.0 и PSNR-UV ≥ 34.0 дБ.

## ❓ FAQ (Часто задаваемые вопросы)

**1. Насколько широка поддержка формата JXL?**  
Нативная поддержка реализована в macOS 14 (Sonoma) / iOS 17+, Chrome 91+ и Firefox 128+. Однако в экосистеме существуют известные ограничения:

- **Анимации**: Современные анимированные форматы (JXL/AV1/HEIF) часто не воспроизводятся как анимация в стандартном приложении «Фото» на macOS/iOS или в Finder (отображаются как статические изображения), особенно при синхронизации через iCloud. Рекомендуется использовать для просмотра современные браузеры или специализированные инструменты командной строки.
- **Эскизы**: Файлы JXL с **ICC-профилями в градациях серого** могут отображаться в Finder/iCloud как **черные эскизы**, хотя сами файлы открываются и отображаются корректно.  
  JXL остается лучшим форматом для побитово точного архивирования и хранения HDR-контента высокой четкости.

**2. Как обрабатывается HDR10+?**  
Полная поддержка реализована! Мы используем `hdr10plus_tool` для извлечения динамических метаданных SMPTE 2094-40 и их последующей инъекции в поток HEVC через параметр `--dhdr10-info` кодировщика `libx265`. Для работы функции убедитесь, что инструмент установлен.

**3. Почему пропускаются форматы WebP/AVIF/HEIC?**  
Эти форматы уже являются современными и высокосжатыми. Повторное кодирование приведет к «поколенческой потере качества» (generational loss) при минимальной экономии места.  
**Исключения**: Инструмент _обработает_ эти файлы, если обнаружит высокоточные **HDR Gainmaps** для синтеза в JXL или если анимированный файл требует оптимизации через движок **Loop Intent (v3)** (который использует 7-уровневое дерево решений для идентификации мемов, стикеров и циклов).
